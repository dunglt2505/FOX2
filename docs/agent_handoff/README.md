## Before any CHAT assignment: apply relevant Skills in order

1. **CHAT-FIRST:** read the relevant installed FOX2 Skills *in the present session* using the available skills tool. For any executable Agent handoff, always use `fox2-source-resolver`, `fox2-agent-route-runtime`, `fox2-governance-preflight`, `fox2-agent-prompt-builder`, and `fox2-document-publication`. Use `fox2-result-review` for every material Agent result, `fox2-feature-certification` when certifying a feature, and `fox2-source-sync` for Git/Library copies. The actual Skill URI/read status must be recorded; naming a Skill is not evidence it was read.
2. **POLICY_CHECK / TASK_STATE_CHECK / R0–R7:** verify current task/results before repeating anything; resolve current *authorized* Dictionary through Registry/release evidence, not lexicographically highest versions. Verify Git source bytes separately from Owner authority. Determine correct work phase and only material gates. Compare CHAT, COPILOT, CODEX, WORK and any other eligible Agent; report actual access/quota or UNKNOWN. Verify writer/worktree, allowed paths, frozen source, no-replay, acceptance, exact role/model/thinking and STOP.
3. **Owner authority:** Policy v2.0.0 establishes the Owner as FOX2's highest internal authority. An explicit Owner override of a named internal gate is `AUTHORIZED_BY_OWNER_OVERRIDE` and preserves historical `BLOCKED/NOT_RUN/FAIL`. It does not make unrun tests PASS, supply inaccessible host capability or approve broker/LIVE by implication. Check the exact authorized scope.
4. **Git-first prompt BEFORE executable assignment:** publish the exact task and prompt text to allowed non-main Git paths in the existing Whole-WP; independently fetch immutable commits/blobs, calculate SHA-256, verify changed paths, then bind the source-set, task, prompt, route and preflight/Owner override. Draft prompt *in chat* is NOT published. Do not issue final executable assignment or falsely label `PASS_TO_ASSIGN` while material checks are UNKNOWN/BLOCKED unless a specific Owner override is independently evidenced.
5. **Agent delivery AFTER execution:** Agent or approved delivery owner pushes code/report/evidence to its authorized non-main Git scope. Terminal text, a Git push alone or a prompt publication are not `COMPLETE`. CHAT independently fetches result SHA, changed paths, tests, report and evidence, applies `fox2-result-review`, then records `ACCEPT/REWORK/HOLD`. If push/receipt is missing or start-state uncertain, report `DELIVERY_BLOCKED/NEEDS_RECONCILIATION`, not a fabricated PASS/replay.
6. **No process inflation:** one existing Whole-WP, risk-appropriate gates and bounded source changes. CHAT performs directly anything its real connectors allow.
