# FOX2 Agent Routing Index v1.5.0 — Agile Lite

**Approved by Owner:** 2026-10-22. **Project-wide management scope.**
**Controlling Policy:** FOX2 Policy v2.1.0.
**Supersedes:** Routing Index v1.4.0 for new/re-scoped CHAT-managed work. Historical Bridge Dispatches and source locks unchanged.

## One task, one execution decision

CHAT owns task completion and first checks whether it can deliver directly. For work requiring host-only coding, select the available capable CODEX or Copilot route by *residual task* complexity, risk, actual permission/capability, cost and expected result. WORK only for truly independent critical audit.

Routine reversible development does not need a separately recorded R0-R7 worksheet, preflight certificate, immutable prompt publication or Bridge Dispatch. Use one task record with objective, allowed scope, actor/model when needed, tests, output and any safety stop.

Select appropriate model/thinking for the actual step; do not default to High solely because the overall feature is complex. Keep a pinned model for ongoing/consumed tasks; do not re-route without material reason.

## Technical controls only when they apply

Where the **chosen** execution path actually depends on Bridge-controlled immutable Dispatch, enforce its active source lock, PreExec, permission, writer, result and no-replay contracts. For high-consequence provider/broker/LIVE, destructive operations, installation/host lifecycle, credentials and other irreversible actions, retain necessary checks and Owner approval if needed.

Never treat Owner approval as proof that unrun technical checks passed, or as permission to operate a provider. Historical FAIL/BLOCKED/NOT_RUN remains unchanged.

## Completion

Agent returns concrete code/artifact, changed files, actual tests and remaining defects. CHAT checks result against task acceptance; mark DONE, REWORK or BLOCKED on the **same** Kanban task. Reuse verified evidence and repair ordinary mistakes in place.

## Source/version selection

Governance Policy and Routing for new CHAT management work are resolved from the authorized projectwide Governance Registry; machine-bound contracts resolve separately from their pinned Dictionary for the specific actual runtime. Preserve old references when historical or compatibility-only. No blanket Policy/BRD/TechSpec/Dictionary version bump.
