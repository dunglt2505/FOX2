## 3. WP acceptance details and negative tests

### P2-01 — Foundation / API Contract

- **P2-01 design-lock candidate — DTO families:** use separate `MarketDataEnvelope` v0.4 (`{contract_version, request_id, generated_at, data}`), `ProcessHealth`/`SourceHealth`, `InstrumentSearchResult` and `WatchlistPreference` DTO families as defined by the published Contract. Do not apply market-observation schema to health, preferences or instrument-search payloads; do not invent a contract version.
- **P2-01 validator boundary:** implement separate *shape/schema* and *semantic* validation interfaces. Market semantics include positive quote price (not merely schema's numeric zero allowance), OHLC bounds, time order, genuine-zero volume vs missing, observation/available timestamps and unit/basis/rights/freshness where applicable. Do not claim semantic PASS from a JSON-schema PASS. `generated_at` is response creation time, not a replacement for market event/observation time. No market routes outside the published Contract.
- **P2-01 interface/port freeze (design signatures, final exact Python types to be pinned in a future WP source task):** `MarketValidator.validate_shape(payload, kind) -> ValidationResult`; `MarketValidator.validate_semantics(observation, capability_context) -> SemanticVerdict`; `StoreReadPort.get_observation(instrument_id, capability, at_or_before) -> ObservationOrUnavailable`; `StoreWritePort.append_and_promote(candidate, ingest_audit) -> CommitResult` (future P2-02); `DSMSelectPort.select(capability, instrument_id, use_context) -> SelectionDecision` (future P2-03); `PreferenceRepositoryPort.replace_if_version(expected_version, items) -> PreferenceResultOrConflict` (future P2-02/P2-04). These are *language-neutral conceptual contracts*, not authorized code definitions. Lock argument semantics, error classification, nullability and ownership before any executable P2-01 handoff.
- **Dependency direction:** DTO/domain validators must not import FastAPI, SQLite, DSM, provider SDK or runtime fixture modules; API → application service/DSM → Store **interfaces**; Store must never depend on DSM/router/provider. Provider transport remains disabled/no constructed network client by default. Runtime diagnostics before actual wiring may describe configuration and `UNAVAILABLE`/`UNKNOWN`, never claim `READY`.
- FastAPI loopback `127.0.0.1`, provider/network disabled by default. GET health and public diagnostics return explicit sanitized states; inaccessible input must return `UNAVAILABLE`/`UNKNOWN`, not fabricated prices.
- Reject accidental provider-secret environment echo, upstream network at offline startup, broker account or order routes, synthetic fixture imports from investor runtime.
- Evidence: pinned contract hash, command/version/log summary, passing offline unit/schema/negative tests, zero unexpected network attempt under measured offline harness, security checks of route table.
- **Frozen planning subset (WP evidence only):** `FOX2-00-T01/T02/T03/T04`, `FOX2-06-T05/T13/T14/T16/T18`, `FOX2-N1-T01/T02/T03/T04/T12`. Cover only offline validator/configuration/fixture-boundary portions; applicable full scenarios require P2-03/P4/M1-B evidence. Per-case attribution follows the traceability table below; never blanket PASS.

### P2-02 — Transactional Store

- SQLite tables for `instruments`, `observations`, `bar_revisions`, `current_projection`, `gaps`, `selection_audit`, `rights_registry`, `watchlist_preferences`; schema version/migration. A real market observation is append-only/revisioned; no synthetic into production store.
- **P2-02 required pre-DEV design lock:** freeze observation receipt identity separately from *market bar identity* (`source/provider/instrument/venue/board/timeframe/start/basis`, revision/correction lineage), as required by BRD-06 R17 and the Contract. Identical polling may record a receipt/audit but **must not mint a new market revision**. Corrections append immutable revision with `first_available_at` equal to the *actual first local observation* of that correction; never backdate or rewrite an earlier availability. Mixing raw/adjusted basis without explicitly segregated identities is forbidden.
- **Promotion/current pointer:** an out-of-order arrival never auto-promotes based on receipt time; promote only a deterministically verified more-current/final/corrected valid revision in the **same identity/basis series**. Ambiguous order, missing finality or invalid semantics must retain prior valid pointer with gap/partial/unknown diagnostic rather than silently regress the view. Define tie-break ordering/idempotency and read snapshot guarantees in P2-02 task before writing code. Store readers see transaction-consistent observations/revisions/current/audit.
- **Atomic transaction and writer:** one bounded ingest writer commits observation, revision, current pointer and ingest audit together, or rolls back all. Never hold a DB write transaction across a network await. Apply bounded SQLite busy/retry/failure behavior; failures retain previous current pointer. A DSM selection/read audit is a separate operation and must **not** create a market revision. Request-local metadata cannot be a shared `last_metadata` across concurrent requests. Source/time/unit/basis remain explicitly `UNKNOWN` without accepted mapping.
- Negative: injected failure before/after each transactional stage, interrupted transaction and reopen, idempotent repeated polling, duplicate/correction/out-of-order/ambiguous finality, reader/writer race, writer collision/busy timeout, expired rights on restart, orphan current pointer, cross-basis promotion and prohibition on writing/reusing legacy FOX store.
- Evidence: migration/checksum/version, deterministic offline fixtures and rollback/race tests, persisted record identity hashes, restart verification.
- **Frozen planning subset:** `FOX2-06-T10/T11/T12/T17/T21/T23`, `FOX2-N1-T05/T06/T07`. P2-02 proves transactional/persistence/backend subcases only; actual provider rights/revocation remains blocked for P5–P7 until authorized.

### P2-03 — DSM Source Selection

- **Typed capability and evaluation-at-use:** DSM differentiates `QUOTE`, `BARS`, and `INDEX` requests; historical close must never impersonate latest trade/quote. For **each** service/read/selection (not just startup), reevaluate rights (`read`, `redisplay`, `retained_use`) and expiry, provenance, unit/time/basis/instrument/calendar mapping, actual freshness and relevant gaps. Never serve a cached positive selection after expired/revoked rights; no stale unauthorized store fallback. `LIVE` requires valid current evidence, while `PROVIDER_NATIVE_UNVERIFIED` remains diagnostic-only.
- **Transport-disable boundary:** `provider_enabled=false` blocks constructing/using provider network transport and all provider operations (startup, manual refresh, retry, scheduler, backfill); even an API request cannot cause an upstream call. Fixture/test sources must be isolated and never fallback into investor runtime. Unavailable diagnostics carry sanitized reason and `selection_audit_id`, with observation/source IDs/times `null` when missing under the published schema.
- Offline sources only in P2; isolated fixtures in test harness. No transparent fallback from missing provider to synthetic investor values. Every decision records `selection_audit_id`, rejected candidates and reason codes without private data.
- Negative: provider disabled, entitlement expired, stale snapshot, missing mapping/calendar, quote/historical mismatches, no-trade vs outage, incomplete bars with gaps and unknown time basis.
- Evidence: source-decision matrix per capability, negative tests with source/set/revision, no-network proof, repeatable diagnostic trace.
- **Frozen planning subset:** `FOX2-06-T02/T03/T04/T07/T08/T09/T15/T16/T18`, `FOX2-N1-T01/T02/T07/T09`. Only offline simulated state, expiry, no-network, gap and capability evidence belongs to P2; provider/WS-specific obligations remain `NOT_RUN` until later authorized M1-B checkpoints.

### P2-04 — API, Watchlist, Offline Integration

- Implement only approved endpoints: `GET /api/health`, `GET /api/data-sources/health`, `GET /api/market/overview`, `GET /api/stocks`, `GET /api/stocks/{symbol}`, `GET /api/stocks/{symbol}/bars`, `GET/PUT /api/watchlist`.
- Provider-down **valid** symbol yields a capability-typed status-safe `UNAVAILABLE`/permitted `STALE` envelope; unknown symbol 404; invalid query 422; unsafe store 503. Query/search length/limit/cursor bounded. No `BARS`/history fallback into `QUOTE`, no raw licensed provider data or secret in error responses; reevaluate rights/freshness at every request through DSM.
- **Watchlist ownership and CAS:** P2-02 owns SQLite `watchlist_preferences` schema/migration and transactional repository interface; P2-04 owns the preference service/HTTP behavior, not a competing migration. `PUT` calls atomic `replace_if_version(expected_version, items)` so compare/version increment/new list/`updated_at` commit in **one** write transaction. Concurrent stale request → 409 without lost update; invalid/unknown/duplicate or >100 verified IDs → 422; DB failure → sanitized 503 and rollback with unchanged version/list; restart preserves preference. Never call broker/provider from preference mutation.
- Enforce loopback Host/Origin and JSON content-type on preference PUT. Browser will only call backend in P3. No profile broker write, token/secret exposure, phantom quote from historical close, or blocked account endpoints.
- Evidence: HTTP contract snapshots, negative-case/status test logs, restart persistence, no secret/reference leak, scoped Git diff and immutable result receipt.
- **Frozen planning subset (backend sub-evidence):** `FOX2-08-T01/T02/T04/T07/T10/T11/T13/T14`, `FOX2-06-T13/T14`, `FOX2-00-T03`, `FOX2-N1-T10/T11`. `FOX2-08-T05` requires real WebSocket and belongs to P6/P7, **not full P2 PASS**. UI inspection/navigation/responsive (`FOX2-08-T02/T04/T08/T09/T12`) must retain full-test obligation at P3/P4. Milestone closure `FOX2-00-T05` belongs to P4/P7.
