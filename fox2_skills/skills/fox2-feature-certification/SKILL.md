# Assess feature behavior from actual installation and acceptance evidence

- Identify the exact feature and requirements; support any FOX2 feature, not Bridge only. Inspect what was actually installed, invoked and observed.
- Map each acceptance item to its independent behavior evidence and tests. Separate discovery, contract preparation, model invocation, domain behavior and production release.
- Report a bounded technical acceptance result and gaps. Source-only code or unit assertions cannot prove installed behavior.
- Under conditional authority, technical findings still proceed but release/canonical certification remains pending. Never fabricate a working installation or promote EFFECTIVE from helper PASS.

Read [scope and source guidance](../../shared/host_guidance.md) when authority, canonical sources, task state or effects matter.
