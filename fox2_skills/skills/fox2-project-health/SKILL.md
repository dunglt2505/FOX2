# Report project health from acceptance evidence

- Establish the evidence cutoff and acceptance items. Read available test, installation and runtime receipts; distinguish attempted, passed, failed and unobserved outcomes.
- Reconcile each claim to its evidence. A commit, upload, helper result or author's self-report alone is not installed-behavior acceptance.
- Report verified facts, unknowns, blockers and the next milestone. Preserve existing completed work and identify material contradictions.
- An evidence-based technical health report may proceed under a conditional baseline. Keep release readiness and source authority separate; do not create an authoritative status from missing facts.

Read [scope and source guidance](../../shared/host_guidance.md) when authority, canonical sources, task state or effects matter.
