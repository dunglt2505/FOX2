# fox2-agent-prompt-builder

## Agile Lite Owner-approved operating precedence (2026-10-22)

Apply project-wide Policy v2.1.0 and shared `../shared/operating_rules.md` as the common management model. Routine authorized reversible work uses one Kanban task -> implementation -> appropriate tests -> CHAT acceptance. Historical mandatory R0-R7 / PreExec / immutable Git prompt / Dispatch language below applies ONLY if the selected actual Bridge/irreversible technical transport requires it; it is NOT an administrative prerequisite to ordinary native DEV. Preserve all substantive domain, technical safety, immutable historical and no-replay instructions. Do not cascade version-reference edits without material consumer impact. Installed plugin version remains distinct from this source candidate.

## Activate when
Any NEW Agent assignment or task transfer CHAT→WORK/CODEX/Copilot or WORK→CHAT NEW/uncompleted task; not an original assignment result return and not CHAT direct work.

## Work to perform
Resolve task/owner/approved source and testable acceptance; choose CHAT direct action first. For residual execution, specify Role, exact Model/Thinking, source/Dispatch lock, scope, one-writer/allowed paths, permissions, appropriate preflight and STOP. For code include concise K1 trace requirement: every material diff hunk maps to REQUESTED/NECESSARY_DEPENDENCY/JUSTIFIED_GENERATED; no drive-by refactor.

## Completion / stop
Assigned residual is precise, minimal, authorized and has objective completion evidence; otherwise HOLD the executable portion.


For routine independent internal work follow the Agile Lite rule above. The controlled-route contract below applies only to an execution path that actually needs immutable Bridge or consequential safety evidence.

## Legacy controlled-route execution contract (conditional)
- **TRIGGER:** Any NEW Agent assignment or task transfer, including CHAT→WORK/CODEX/Copilot and WORK→CHAT NEW work; not an existing Agent RESULT_RETURN or direct CHAT task.
- **PRECONDITIONS:** Owner-authorized scope, resolved source/task/attempt, R0–R7 route and actual host capability; determine whether Owner manually launches a Windows CLI.
- **REQUIRED_ACTIONS:** Direct-first; bind Role/Model/Thinking/Scope/STOP and Git result contract; publish exact task.md/prompt.md with readback where required; prepare verified PowerShell launcher if manual Windows CLI.
- **REQUIRED_EVIDENCE:** Immutable task/prompt commit/path/blob SHA-256, permissions/preflight and one-writer/no-replay checks; confirmed CLI syntax/version for a launcher; evidence of rendered Owner-visible answer is distinct from Git.
- **DELIVERABLES:** Git task+prompt and delivery obligations; Owner-facing message containing full executable `powershell` block when manual Windows CLI is authorized and supported, or explicit HOLD with missing prerequisites.
- **VALIDATION:** Before final response compare prompt/source binding, allowed paths, attempt identity and rendered script completeness; if `OWNER_MANUAL_EXECUTION=YES`, inspect the ACTUAL response content—not just the file/plan—for PowerShell; do not claim proof of rendering if not observed.
- **FAILURE_STATE:** `HANDOFF_INCOMPLETE` when Git/result contract or required visible script is absent; `HOST_NOT_VERIFIED` / `EXECUTION_HOLD` on missing capability/permission/PreExec or consumed attempt.
- **COMPLETION_GATE:** `OWNER_LAUNCH_READY` only when all applicable immutable, host, rights, one-writer and actual inline Owner-delivery checks pass; this does NOT mean Agent executed. Otherwise bounded HOLD/PARTIAL and next safe action.

## v0.3.7 — PowerShell 7+ code generation for Owner-operated Windows Agent CLI
For any Windows/CLI Agent handoff requiring Owner-operated PowerShell, `fox2-agent-prompt-builder` MUST write the **entire executable launcher, prechecks, Git binding verification, STOP guards, and result-pickup instructions as PowerShell code targeting PowerShell 7 or newer**. The only supported interpreter for these scripts is `pwsh` (`pwsh.exe` on Windows), not Windows PowerShell 5.1 (`powershell.exe`).
The first executable preflight in the generated script MUST fail closed if `$PSVersionTable.PSVersion.Major -lt 7`, before mutation, checkout, process launch, or Agent execution. Verify the actual installed `pwsh` path/version and supported Codex/Copilot CLI syntax; if missing/unknown, return `HOST_NOT_VERIFIED` or `EXECUTION_HOLD`, never a guessed executable script.
The full, **non-placeholder**, copy-ready `powershell` script MUST appear directly in CHAT's response whenever Owner manual execution is requested. Script and published immutable task/prompt must match; enforce one-writer, PreExec, permissions, no-replay, and authorized attempt identity. This applies to **execution/launcher code generated by Prompt Builder**, not to the application implementation language prescribed by FOX2 TechSpec. A source-bound Git task/prompt without the required inline launcher is `HANDOFF_INCOMPLETE`, never `OWNER_LAUNCH_READY`.

## Bridge / immutable Git-first Agent handoff (conditional)
1. CHAT checks R0 task/evidence, R1 stage, R2 Policy/authority/risks, R3 real Agent/host capability and quota, R4 CHAT/COPILOT/CODEX/WORK cost, R5 worktree/writer, R6 Git source/delivery, R7 Role · Engine/Model · Thinking · Scope · STOP. Use existing Whole-WP; do not create administrative micro-WPs.
2. Resolve *latest authorized/effective* Registry/Dictionary/source-set; select BRD/Tech Spec/acceptance, then freeze exact commit and SHA-256 in the task. Owner-approved candidate/override is recorded separately from technical PASS.
3. CHAT writes final task + **exact executable prompt** in authorized non-main Git paths; push and fetch/readback immutable prompt commit, blob SHA-1 and SHA-256 BEFORE final assignment. A prompt displayed only in chat is a DRAFT, not an issued Agent task. Any Dispatch binds that exact Git prompt without changing an old/consumed identity.
4. Final Agent prompt specifies Git checkout/pickup at exact SHA, allowed worktree/files, one writer, chosen COPILOT/CODEX, model/effort, rights, one attempt, tests and objective acceptance. Require Agent to push actual code (if any), `reports/<WP_ID>/report.md` and `reports/<WP_ID>/evidence_manifest.json` conforming to Dictionary-resolved Result Contract; give observed remote result SHA outside committed report (no self-reference).
5. Completion is a valid handoff source and selected, authorized route, NOT successful Agent execution. CHAT later applies `fox2-result-review` to the remote result, issues ACCEPT/REWORK/HOLD. Missing Git prompt, source or host proof => HOLD only affected executable action; do direct preparatory work first.

## New work: consume one resolved source set, never own current-version copies
Call the source resolver and stage-aware preflight; record the exact selected Owner human operating rule and separately compatible machine source-contract identity, with release/runtime status. Do not manually copy or hard-code a `current Policy` number in prompt templates. For actual executable work freeze immutable commit/path/SHA-256 for all material sources, source-set scope, approval proof, route-specific compatibility and task ID; no final Agent/Dispatch issue when any required task/source lock is missing. Existing pinned Dispatches must not be reissued/rebound. In the 2026-10-19 scoped human operating case, CODE-FIRST may set next-task priority now while Bridge machine adoption remains `NOT_ATTESTED`; do not suppress a real route-specific PreExec or fabricate machine PASS.

## Scoped human source rule
Consume `OWNER_APPROVED_PRINCIPLE` only for a duly evidenced Owner-approved scope; keep `PUBLISHED_EFFECTIVE` and `RUNTIME_ENFORCED` separate. Never turn old Dispatch into a new task or skip real material gates.

## Full-delivery responsibility
A prompt is an intermediate artifact, not the Owner's goal. If authorized to issue an executable task and all gates are met, CHAT must publish/read back the exact Git task and prompt, complete the allowed assignment, and retain responsibility for later Git result review. Do not send WORK merely to write/read routine prompts. Stop only at an actual permission, capability, safety or asynchronous dependency; never label an Agent handoff DONE or pretend to work in the background.

## Bridge bidirectional task and Git delivery contract (conditional) (v0.3.5)
`NEW_TASK_HANDOFF_IN_EITHER_DIRECTION → PROMPT_BUILDER_REQUIRED`. This includes CHAT→WORK, CHAT→CODEX, CHAT→Copilot, and WORK→CHAT when WORK transfers a genuinely NEW/uncompleted task for CHAT to accept. For WORK→CHAT, WORK supplies a source-bound Prompt-Builder-compatible task/handoff artifact; CHAT verifies and finalizes acceptance using this Skill before acting or issuing a new Agent assignment. WORK may not grant Owner authority or bypass route checks. A WORK→CHAT RESULT_RETURN of the ORIGINAL assignment is **NOT** a new task: follow Git Result Contract + `fox2-result-review`, do not generate another prompt.
Before issue, determine READ_ONLY_AUDIT vs host-only/coding and resolve the actual authorized branch/path plus delivery capability. Produce immutable `task.md` + exact `prompt.md` on approved non-main Git and verify prompt commit/blob SHA-1/SHA-256 where Git-first requirements apply. Every WORK audit prompt requires real `reports/<WP_ID>/report.md` + `reports/<WP_ID>/evidence_manifest.json`, evidence citation paths, allowed report-only writes, a named Git result branch and observed remote SHA supplied outside committed report; no code write for read-only audit. Other Agents use the same two result artifacts plus code/tests as applicable. Verify WORK Git push capability; if unavailable, predefine actual file-byte export and CHAT-published Git delivery, preserve author/publisher provenance and mark pending until real readback. Never claim chat prose is delivered files.
For verified Windows/CODEX/Copilot CLI invocation, create *complete, scoped PowerShell 7/Windows-compatible invocation instructions*: immutable prompt-ref/path, safe source/task verification, branch/worktree/one-writer checks, capability/auth/preflight/rights checks, explicit STOP before any mutation, correct supported CLI syntax for observed installed version, one permitted attempt and result pickup. If Owner must copy commands, paste the ENTIRE executable `powershell` script in the CHAT response (not just a link or file path); no placeholders, imaginary executable, fake PreExec or undocumented full-access flag. For WORK cloud-only tasks or CHAT read-only reviews, do not fabricate PowerShell/WORK CLI. Prompt Builder creates an execution contract, not permission to invoke an Agent without proven route.
