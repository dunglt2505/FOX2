# fox2-brd-change-control

## Agile Lite Owner-approved operating precedence (2026-10-22)

Apply project-wide Policy v2.1.0 and shared `../shared/operating_rules.md` as the common management model. Routine authorized reversible work uses one Kanban task -> implementation -> appropriate tests -> CHAT acceptance. Historical mandatory R0-R7 / PreExec / immutable Git prompt / Dispatch language below applies ONLY if the selected actual Bridge/irreversible technical transport requires it; it is NOT an administrative prerequisite to ordinary native DEV. Preserve all substantive domain, technical safety, immutable historical and no-replay instructions. Do not cascade version-reference edits without material consumer impact. Installed plugin version remains distinct from this source candidate.

## Activate when
User proposes or inspects BRD behavior, retention, customer eligibility or a requirement delta.

## Work to perform
Compare original/candidate passages, downstream API/data consumers, acceptance and migration; classify semantic vs editorial. Prepare separate candidate only when authorized, then read back; do not promote existing business terms or request new approvals for decisions already proven.

## Completion / stop
Diff, impact and open consumers explicitly documented; effective change held until approved authority and publication.


Completion is governed by the **Execution Contract v0.3.6** below; apply conditional obligations only when triggered, report bounded HOLD otherwise.

## Execution Contract v0.3.6 — observable completion
- **TRIGGER:** BRD requirement change, interpretation, retention/eligibility delta, candidate publication or downstream semantic assessment.
- **PRECONDITIONS:** Identified current BRD authority, proposed change, affected Whole-WP and authorization for any write.
- **REQUIRED_ACTIONS:** Diff business semantics separately from editorial changes; trace TechSpec/API/data/acceptance consumers and migration; prepare candidate without promoting effectivity.
- **REQUIRED_EVIDENCE:** Exact source/candidate passages, source identities and verified impacted consumers, including explicit UNKNOWN where inventory incomplete.
- **DELIVERABLES:** Delta summary, consumer-impact map, acceptance changes and candidate/source references if created.
- **VALIDATION:** Cross-check semantic impact and negative cases against BRD and consumer versions; verify authorized candidate readback when written.
- **FAILURE_STATE:** `IMPACT_UNVERIFIED` / `CONSUMER_UNKNOWN` / `PUBLICATION_HOLD` for missing dependencies/authority.
- **COMPLETION_GATE:** Delta and affected consumers documented with testable acceptance, source status and lawful next action; EFFECTIVE requires separate approved publication.
## Document authority & handoff effect
Resolve BRD identities through current trusted Dictionary, not by a header or filename. BRD retains its own content version; an identity-only Policy/Dictionary bump does not force a BRD semantic bump. For approved semantic change map Tech Spec, API, contracts, consumer tests and acceptance; update a bound *future* task only after a new authorized source-set. A BRD candidate is not automatically effective. If this change needs Agent coding, apply the Git-first `fox2-agent-prompt-builder` sequence; CHAT reviews actual Git results.


## v0.3.7 — Project-wide focused correction and PASS preservation
FOX2 all stages: earliest causal divergence. Accepted PASS is REUSE_VERIFIED by default; no blanket recheck. Retest only changed fact→affected gate or mandatory gates. CONSUMED Attempt cannot replay; accepted PASS evidence from it is reusable. NOT_RUN/UNKNOWN remain scoped.
