# fox2-governance-preflight

## Agile Lite Owner-approved precedence

Current project management: Policy v2.1.0 and `../shared/operating_rules.md`. Ordinary internal task: goal, implementation, proportionate tests, CHAT review, DONE or REWORK. Mandatory old source lock/PreExec/Dispatch/extra review applies only to the actual Bridge or consequential execution path that requires it; do not impose Bridge gates on unrelated DEV. Preserve real security, no-replay, existing task pins and domain-specific assessment.

## Activate when
Task asks readiness, permission or pre-execution evaluation.

## Work to perform
Classify READ_ONLY / AUTHORIZED_CANDIDATE_WRITE / AGENT_EXECUTION / RELEASE. For last two require independently proven authority, task lock, preflight and correct actor. Do not synthesize certificates; preserve existing signed receipts.

## Completion / stop
Explicit stage, required vs observed gates, blockers and permissible next step.


For routine independent internal work follow the Agile Lite rule above. The controlled-route contract below applies only to an execution path that actually needs immutable Bridge or consequential safety evidence.

## Legacy controlled-route execution contract (conditional)
- **TRIGGER:** Pre-execution readiness, permission/capability checks or proposed executable Agent/host action.
- **PRECONDITIONS:** Classified action type (`READ_ONLY`/`CANDIDATE`/`DEV`/`RELEASE`) plus Policy/task/source/actor.
- **REQUIRED_ACTIONS:** Identify materially applicable PreExec rather than demand unrelated Bridge gates; check authority, source lock, writer, capability, permissions and no-replay.
- **REQUIRED_EVIDENCE:** Observed host/authorization/PreExec receipts and locked source, clearly separated from historical records or scoped Owner override.
- **DELIVERABLES:** Required-vs-observed gate table, `GO`/`HOLD`/`AUTHORIZED_BY_OWNER_OVERRIDE` and exact limited next action.
- **VALIDATION:** Fail closed for affected executable action if required proof missing, while safe READ_ONLY tasks need no fabricated execution precheck.
- **FAILURE_STATE:** `PREEXEC_BLOCKED` / `CAPABILITY_UNKNOWN` / `ASSIGNMENT_HOLD` (retain original FAIL/NOT_RUN).
- **COMPLETION_GATE:** Bounded stage-specific verdict with evidence; GO never confers merge/Canary/LIVE or wider rights.
## Pre-issue vs post-result
For selected Bridge/controlled executable handoffs verify Policy/Task State/R0–R7 and material route-specific capability, one writer, permission, exact Git task/prompt and readback. Normal `PASS_TO_ASSIGN` comes only from real task PreExec PASS; a **specific Owner override** may permit action with `AUTHORIZED_BY_OWNER_OVERRIDE` while the old receipt remains BLOCKED. For safe CHAT read-only/candidate work do not fabricate an Agent PreExec. Installed Bridge status is material only to routes actually dependent on Bridge. Final assignment still requires task and prompt in Git; result completion requires Git report, evidence and CHAT intake.

## New Task Binding Gate (stage-aware)
Before new coding/Agent execution, consume the source resolver's **scoped human decision** and separate **machine interface** result. Policy v2.1.0 outcome-first governs new human task management in approved scope; Bridge machine support does not follow from that approval. Classify `READ_ONLY`/`CANDIDATE`/`DEV`/`INTEGRATION`/`OPERATIONAL_RELEASE`. Source-lock/permission/one-writer/actual route-specific PreExec and Git task/prompt remote readback are mandatory for each new executable route unless a specific Owner override lawfully waives an internal gate with the original failure preserved. A Bridge-only installed prerequisite must not block *genuinely Bridge-independent offline DEV*; do not relabel a blocked Bridge Dispatch as native DEV. If immutable task SHA is missing, `HOLD_EXECUTABLE_BINDING`, never issue Dispatch. Runtime incompatible => `RUNTIME_NOT_ENFORCED` and HOLD only dependent execution, not all human CODE-FIRST planning. Old Dispatch stays pinned/no-replay. No auto LIVE/merge/provider/broker rights.

## Scoped human source rule
Consume `OWNER_APPROVED_PRINCIPLE` only for a duly evidenced Owner-approved scope; keep `PUBLISHED_EFFECTIVE` and `RUNTIME_ENFORCED` separate. Never turn old Dispatch into a new task or skip real material gates.

## Continue unblocked stages
A failed or missing gate stops only the action it materially controls; CHAT still completes authorized source inspection, candidate prep or verification. If a new Owner decision is genuinely required, name the scope; do not ask again for an evidenced identical approval. No “automatic execution” follows a readiness check; preserve one writer, immutable lock, permission, installed capability and no-replay.

## WORK read-only audit versus coding execution (v0.3.5)
Classify scoped CHAT/WORK read-only research and report-only permitted writes separately from executable CODEX/Copilot/host Agent Dispatch. Do not invent coding PreExec for WORK read-only audit; apply actual source authority, permitted Git report write, immutable task/prompt binding and any material route-specific gate. A PowerShell script is a user-visible execution vehicle, never an override of missing evidence. A failed dependency holds only affected executable stage; direct safe artifact preparation remains possible.


## v0.3.7 — Task-level selected-route verification (not classification)
For controlled-route NEW executable tasks, read `TASK_ROUTE_ASSESSMENT` and the selected Actor/Model/Thinking tuple. Verify matching task/prompt/source, authority, host/model/effort support, auth/capacity, scope/writer, rights, no-replay and material gates. `PreExec MUST NOT infer task complexity`, choose default high, silently downgrade Thinking, swap Agent or auto-fallback. On BLOCKED/UNKNOWN return to CHAT for justified route decision; never mutate pinned artifacts. CHAT read-only work needs no invented PreExec. No historical host PASS upgrades to new runtime proof.

## v0.3.7 — Domain-specific bounded recovery
Recheck only gates invalidated by changed inputs, host, permissions, time-dependence or source binding, plus mandatory new-attempt PreExec. No waiver of no-replay or required stage gates; record rationale for every reused gate.


## v0.3.7 — Project-wide focused correction and PASS preservation
FOX2 all stages: earliest causal divergence. Accepted PASS is REUSE_VERIFIED by default; no blanket recheck. Retest only changed fact→affected gate or mandatory gates. CONSUMED Attempt cannot replay; accepted PASS evidence from it is reusable. NOT_RUN/UNKNOWN remain scoped.
