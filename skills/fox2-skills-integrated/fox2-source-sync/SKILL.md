# fox2-source-sync

## Agile Lite Owner-approved precedence

Use project-wide Policy v2.1.0 and `../shared/operating_rules.md`: one Kanban task, actual delivered result, necessary testing, CHAT acceptance. Historical R0-R7/PreExec/Git-prompt/Dispatch requirements apply only to the technical route which materially needs them. Preserve each specialized skill's real technical evidence requirements, protected operations, source history and no-replay. Avoid administrative micro-WPs and version-only churn.

## Activate when
User requests sync/copy/repair existing document sources.

## Work to perform
Identify independently trusted source and exact destination; compare bytes/hash and prior WIP; preserve divergent copies. For allowed write use destination-safe mechanism, verify remote readback; never silently overwrite or promote effective.

## Completion / stop
Source/destination commit or path/hash and SYNCED/PARTIAL/CONFLICT statuses.


Completion is governed by the **Execution Contract v0.3.6** below; apply conditional obligations only when triggered, report bounded HOLD otherwise.

## Execution Contract v0.3.6 — observable completion
- **TRIGGER:** Sync/copy/repair between Git, Library or authorized Agent file-delivery channels.
- **PRECONDITIONS:** Identified source and destination, rights, scope, current WIP and non-overwrite preconditions.
- **REQUIRED_ACTIONS:** Compare bytes/provenance, transfer only allowed artifacts, preserve divergent copy and verify readback.
- **REQUIRED_EVIDENCE:** Source/destination paths, raw hashes, immutable Git identities and delivery receipts where applicable.
- **DELIVERABLES:** SYNCED/PARTIAL/CONFLICT record with before/after hash and pending work.
- **VALIDATION:** Byte-compare from independent readback; verify Agent task/result files when Git is delivery medium, no chat-only PASS.
- **FAILURE_STATE:** `SYNC_BLOCKED` / `DESTINATION_CONFLICT` / `DELIVERY_BLOCKED` on missing evidence/rights.
- **COMPLETION_GATE:** Only claim synchronized when actual destination bytes verified; otherwise classify partial/conflict honestly.
## Lifecycle handoff
For document Git↔Library compare exact bytes and authority independently. For **Agent task/prompt** Git is the transfer channel: publish exact authorized non-main task/prompt Git artifacts then remote-readback before assignment, and require independent CHAT readback of Agent report/evidence after push; do not demand Library copies for ephemeral Agent prompts unless explicitly governed. No direct Git result = no completed handoff.

## Release lifecycle evidence versus ephemeral task handoff
For governed Policy/BRD/TechSpec release, Git publication **and Library bytes/readback** are distinct gates before promoting Dictionary/Registry current for the authorized scope. A failed Library readback is `PUBLICATION_HOLD`; do not claim full sync or advance current. For transient task/prompt handoff, Git-first exact prompt/sha readback remains sufficient when Library publication is not a governed requirement. Keep candidate/approved-human/released/machine-adopted statuses separate; never overwrite divergent WIP silently.

## Scoped human source rule
Consume `OWNER_APPROVED_PRINCIPLE` only for a duly evidenced Owner-approved scope; keep `PUBLISHED_EFFECTIVE` and `RUNTIME_ENFORCED` separate. Never turn old Dispatch into a new task or skip real material gates.

## Agent task and WORK result files are Git-bound (v0.3.5)
For WORK handoff as well as coding Agents, verify matching source task/prompt and result-report/evidence SHA and allowed report branch. Missing push access is not permission to call a chat-only summary Git-delivered: transfer actual bytes by supported channel, CHAT commits if authorized and remotely reads back. Preserve audit author vs publishing actor, original task lock and no-replay. Do not require Library copies for ephemeral task handoff unless another governing contract requires them.


## v0.3.7 — Project-wide focused correction and PASS preservation
FOX2 all stages: earliest causal divergence. Accepted PASS is REUSE_VERIFIED by default; no blanket recheck. Retest only changed fact→affected gate or mandatory gates. CONSUMED Attempt cannot replay; accepted PASS evidence from it is reusable. NOT_RUN/UNKNOWN remain scoped.
