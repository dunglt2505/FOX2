# fox2-thread-handoff

## Agile Lite Owner-approved precedence

Apply Policy v2.1.0 and `../shared/operating_rules.md`. The single project Kanban task tracks actual outcome, tested changes and review. R0-R7/PreExec/Git task-prompt/Dispatch handoff applies only when chosen controlled technical execution needs it; never an automatic gate on ordinary authorized native DEV. Keep domain and technical compatibility tests, real permissions, historical task pins and no-replay; do not trigger unrelated version upgrades.

## Activate when
Genuine conversation/actor/context transfer including WORK→CHAT NEW/uncompleted task; not a substitute for existing Agent result return.

## Work to perform
Capture immutable source/task lock, last reviewed receipt, decisions and blockers, no-replay state, next actor and permission, and tool limitations. Prefer source pointers over full history without losing governing terms.

## Completion / stop
Self-sufficient concise handoff without an unverified PASS or permission grant.


Completion is governed by the **Execution Contract v0.3.6** below; apply conditional obligations only when triggered, report bounded HOLD otherwise.

## Execution Contract v0.3.6 — observable completion
- **TRIGGER:** Transfer of conversation context, actor, NEW work (WORK→CHAT included), or a genuine environment boundary.
- **PRECONDITIONS:** Actual handoff need, immutable source/task, completion/evidence and recipient capability; no handoff for CHAT-direct work.
- **REQUIRED_ACTIONS:** Distinguish CONTEXT_TRANSFER vs NEW_TASK vs EXISTING_RESULT; new Agent task requires Prompt Builder and source-bound Git files.
- **REQUIRED_EVIDENCE:** Observed last receipt/source/attempt, progress, blocker and recipient route; Git task/result records when assignment related.
- **DELIVERABLES:** Self-contained handoff artifact/context with next actor, immutable pointers and STOP; exact Git task/prompt for executable NEW task.
- **VALIDATION:** Check receiving actor has all data; do not reissue consumed attempt or misclassify result return as new task.
- **FAILURE_STATE:** `HANDOFF_INCOMPLETE` / `TASK_REPLAY_STOP` / `RECIPIENT_NOT_VERIFIED` when required continuity or authority missing.
- **COMPLETION_GATE:** Continuation can safely resume with exact current task state; a handoff is never acceptance or completed execution.
## Not a substitute for Git Agent transfer
Conversation thread handoff contains concise immutable source/Owner/task/last review references and honest state; it is not executable Agent authorization. If it requests the next Agent run, CHAT must separately follow `fox2-agent-prompt-builder`: commit task + prompt on Git, exact readback, bind Dispatch/preflight, Agent retrieves from Git and later pushes report/evidence. CHAT must review Git result before marking task complete. A copy-pasted chat prompt alone is DRAFT.

## Handoff only when necessary
Do not substitute a new thread, prompt or WORK handoff for work CHAT can finish in the current thread. Use handoff only for real context/environment boundaries; carry the unfinished goal and exact blocker forward, and never count handoff itself as delivery.

## CHAT↔WORK two-way task versus result transfer (v0.3.5)
Distinguish `NEW_TASK_HANDOFF` from `EXISTING_TASK_RESULT_RETURN` and `CONVERSATION_THREAD_CONTINUATION` before producing artifacts. CHAT→WORK: require Prompt Builder, bound Git task/prompt and result-delivery obligations. WORK→CHAT new work: source-bound task/handoff file, exact unfinished objective, authorized scope, immutable source/attempt, completed/pending work, blockers, actual owner and `NEXT_SAFE_ACTION`; CHAT checks authority and uses Prompt Builder before accepting any new task. WORK→CHAT result of an already-published prompt: do NOT request a fresh prompt; require actual Git `report.md` and `evidence_manifest.json`, remote SHA and `fox2-result-review`. Preserve historical task/Dispatch identity, not repeat or rebind. A conversation or file pointer alone is not a Git-published executable assignment; if required artifacts are absent report `HANDOFF_INCOMPLETE` and continue safe work.
If Owner must execute a supported Windows CLI handoff locally, include complete validated copy-ready PowerShell in CHAT itself. Work cloud browser cannot be launched via an invented `work.exe`.


## v0.3.7 — Project-wide focused correction and PASS preservation
FOX2 all stages: earliest causal divergence. Accepted PASS is REUSE_VERIFIED by default; no blanket recheck. Retest only changed fact→affected gate or mandatory gates. CONSUMED Attempt cannot replay; accepted PASS evidence from it is reusable. NOT_RUN/UNKNOWN remain scoped.
