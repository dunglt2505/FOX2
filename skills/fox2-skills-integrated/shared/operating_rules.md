# FOX2 three-layer Skills operating rules — 0.5.0

Owner-approved 2026-10-22 for ALL FOX2 project tasks. Layer 1 `mgmt` handles one Kanban, task priority, routing, context. Layer 2 `method` handles domain-specific thinking/instructions and acceptance. Layer 3 `tech` handles publication/readback, material host checks, recovery. A Skill is a **method**, not extra permission or an approval board.

**Skill Routing Matrix (Management):** When Owner asks to apply FOX2 Skills and implement, CHAT uses `fox2-mgmt-delivery`'s event-based matrix to choose only relevant Skills, recording `REQUIRED/APPLIED/NOT_APPLICABLE/UNAVAILABLE` based on real invocation, not name recognition. Re-evaluate at assignment, result and acceptance/Plan/Board sync. One Whole-WP; no new 12th Skill, duplicate approvals or mandatory invocation of all Skills. A Skill is guidance, not autonomous Git/Bridge execution.

**Agile Lite:** one logical task, Build → Test → Deliver. CHAT owns end-to-end delivery; call only Skills needed. Native reversible DEV has no automatic R0–R7 worksheet, durable PreExec receipt, Git-published **prompt**, Bridge Dispatch, micro-WP, independent review or forced High model. **This exemption does not waive Git result delivery:** every delegated Agent coding result must reach its authorized Git result branch through Agent or authorized publisher, and CHAT must verify the remote SHA before DONE. WORK report assignments follow their agreed Git/report delivery contract; missing push authority requires explicit authorized publication, not self-declared completion. Reuse accepted evidence and correct small defects within the same task.

**PowerShell/result distinction:** Host-specific `pwsh` 7 or Windows PowerShell 5.1 compatibility must be observed before copy-ready scripts; Git executable variables use the PowerShell call operator `&` and immediate native `$LASTEXITCODE` checks, with no PowerShell alias assumptions. A correctly scoped `TEST_EVIDENCE_ONLY` result may modify only test/report artifacts, not product code, but must carry actual test execution proof and authorized remote Git readback. No code diff is not automatically failure; no executed tests is never PASS.

**Bridge exception:** real Bridge runtime (not Skill prose) owns schema/normalizer, Dispatch v3, PreExec, ledger/no-replay, Agent CLI, **Git publication of results according to actual `delivery_owner=AGENT|BRIDGE`** and worktree/permission boundaries. Prompt Builder writes ONLY task/prompt content; Publishing & Sync verifies committed bytes; Route Preflight inspects real technical guards; Result Acceptance reviews result. Do not infer verified technical PASS from Owner approval or task text.

**Trust and source:** Human current Policy/Router/Protocol and a historic machine-pinned Bridge Policy may differ legitimately. Resolve by scope/real consumer, not filename version; preserve old immutable Dispatches. Avoid secrets in public Git, protected main, unsafe overwrite and provider/broker/LIVE operations absent actual authority. `NOT_RUN`, `UNKNOWN`, `FAIL` remain evidence, never PASS.

**Single owner per responsibility:** mgmt chooses WHAT/WHO, method specifies HOW/GOOD, tech operates/verifies allowed route. No duplicated global management guards copied into every Skill; each Skill states its own inputs/output/boundary for host self-sufficiency. Technical baseline reference files under historical releases are non-normative unless selected installed runtime explicitly uses them.
